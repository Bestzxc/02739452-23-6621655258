2. ปัญหาที่พบและวิธีแก้

ปัญหาที่ 1 — Wongnai ดึงไม่ได้ทั้งที่ robots.txt อนุญาต

อาการ task sources.wongnai.extract ล้มทุกพื้นที่ด้วย RobotsDisallowed ข้อมูลทั้งระบบเหลือ 14 ร้าน (ต่ำกว่า 100)
หาสาเหตุ อ่าน log ของ task ใน Airflow → เปิด robots.txt จริงพบว่าห้ามแค่ /users/ → ทดสอบใน container พบว่า robotparser.read() ใช้ User-Agent ของ urllib แล้วเว็บตอบ 403 ซึ่ง robotparser ตีความว่า "ห้ามทุกหน้า"
วิธีแก้ โหลด robots.txt ด้วย requests + User-Agent ของโปรเจกต์ แล้วส่งให้ rp.parse() เอง (ยังเคารพ robots.txt เหมือนเดิม)

ปัญหาที่ 2 — หน้าเว็บโหลดได้ (HTTP 200) แต่ parse ได้ 0 ร้าน และหน้า 2 ซ้ำหน้า 1

อาการ extract ได้ HTML 560 KB แต่ parser คืน 0 รายการ · พอแก้แล้ว หน้า 2–5 ได้ร้านชุดเดิม
หาสาเหตุ บันทึก HTML ออกมาไล่ดู script ทั้งหมด พบว่าข้อมูลร้านอยู่ใน window._wn = {…} ไม่ใช่ __NEXT_DATA__ ที่เตรียมไว้ · ค้นคีย์ที่เกี่ยวกับหน้าใน state พบว่าเว็บใช้ page.number ไม่ใช่ page
วิธีแก้ เพิ่มการอ่าน window._wn ด้วย json.JSONDecoder().raw_decode และเปลี่ยน URL เป็น page.number → ได้ ~10 ร้านใหม่ต่อหน้า

ปัญหาที่ 3 — load ล้ม: "ON CONFLICT DO UPDATE command cannot affect row a second time"

อาการ extract/transform ผ่าน แต่ wongnai.load ล้มทุกครั้ง
หาสาเหตุ อ่าน error ใน log → ร้านเดียวกัน (เช่น ร้านโฆษณา) โผล่ในผลค้นหาหลายอำเภอ ทำให้ key (source, source_id) ซ้ำกันใน INSERT คำสั่งเดียว
วิธีแก้ ตัดแถวที่ key ซ้ำออกก่อน UPSERT (เก็บแถวเดียวต่อ key)

ปัญหาที่ 4 — แหล่งที่ 3 (Google Places) ต้องผูกบัตร และแผนที่หายเมื่อซูมใกล้

อาการ Google Places ไม่มี key → ถูกข้ามทุกรอบ · บนเว็บซูมเกินระดับ 16 แผนที่กลายเป็นภาพ "Map data not yet available"
หาสาเหตุ Google Places ต้องเปิด billing · ยิงขอ tile ของ Esri ทีละระดับ พบว่าตั้งแต่ระดับ 17 ได้ภาพเดียวกันหมด (ไม่มีข้อมูล)
วิธีแก้ เปลี่ยนแหล่งที่ 3 เป็น Overture Maps (open data ฟรี อ่านด้วย DuckDB) · ตั้ง maxzoom ของ tile เป็น 16 ให้แผนที่ขยายภาพระดับ 16 แทน และจำกัดการซูมที่ 17.5
